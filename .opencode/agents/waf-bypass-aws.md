## WAF Bypass Aws Testing

# AWS WAF Bypass

## Crown Jewel Targets

- Endpoints using only AWS Managed Rules
- APIs without custom rule sets
- Applications behind AWS WAF + CloudFront

## Attack Surface Signals

- `X-AMZ-ID` header confirms AWS
- `X-AMZ-REQUEST-ID` header
- `Server: awselb/2.0` if using ALB
- "Generated by cloudfront (CloudFront)" if CloudFront is in use
- `AWSALB=` cookie

## Step-by-Step Methodology

1. Confirm AWS WAF presence: check for `X-AMZ-ID` or `AWALB` cookie
2. Test managed rules with basic payloads
3. Apply simple obfuscation (case toggling, encoding)
4. Test if custom rules are present (advanced payloads)
5. If only managed rules: simple bypasses often work
6. If custom rules: need more advanced techniques

## Payloads

```html
<!-- XSS - case toggling -->
<SvG OnLoAd=alert(1)>

<!-- XSS - encoding -->
%3Csvg%20onload=alert(1)%3E

<!-- SQLi - comment injection -->
1' UN/**/ION SEL/**/ECT 1,2,3--
```

## Common Root Causes

- AWS Managed Rules are generic and miss context-aware attacks
- Default rule sets have known bypass patterns
- Case toggling and basic encoding bypass regex-based rules
- Customers often rely solely on managed rules without custom rules
